# อ่านสลิปไทยผ่าน LINE + สมุดบัญชีรายรับ-รายจ่าย

> ส่งรูป **สลิปโอนเงิน / ใบเสร็จ / ใบเงินเดือน** เข้า LINE → ได้ข้อมูลมีโครงสร้าง
> และจดรายรับ-รายจ่ายให้อัตโนมัติ — **ไม่ต้องมี GPU ไม่ใช้ LLM รันบน VPS 2 cores ได้**

🇬🇧 [English → README.md](README.md)

---

## ทำไมถึงทำแบบนี้

โปรเจกต์อ่านสลิปไทยส่วนใหญ่ไม่ใช้ cloud API ที่เสียเงิน ก็ใช้ VLM ตัวใหญ่
ตัวนี้ใช้ **PaddleOCR บน CPU** + regex ที่จูนกับสลิปไทยจริง แล้วกลับได้ผลดีกว่า
VLM 3B ที่เคยใช้ ทั้งเร็วกว่าและแม่นกว่า

### ตัวเลขที่วัดจริง

**สลิปไทยจริง 332 ใบ** (กสิกร 255 · ttb 70 · TrueMoney 7) เฉลยมาจากชื่อไฟล์ที่ตรวจด้วยตาแล้ว

| ตัวชี้วัด | ผล |
|---|---|
| ฟิลด์ที่มีเฉลยถูกต้อง (`ref`, `date`, `time`) | **379 / 395 = 96%** |
| เจอยอดเงิน | **332 / 332 = 100%** |
| รูปที่ประมวลผลพัง | **0** |
| ความเร็ว | ~2 วิ (8 cores) · **~8.5 วิ (VPS 2 cores)** |
| RAM | **235 MB** |
| VRAM | **0** |

**ชุดทดสอบเดียวกัน เทียบ 2 engine** — parser เดียวกัน เฉลยเดียวกัน:

| ชุดทดสอบ | Unlimited-OCR 3B (GPU) | **PaddleOCR (CPU)** |
|---|---|---|
| SROIE — ยอดเงิน | 50% | **78%** |
| SROIE — วันที่ | 67% | **98%** |
| `openthaigpt/thai-ocr-evaluation` | 17% | **58%** |

VLM 3B บน GPU 6GB แพ้โมเดล CV ขนาด 215 MB ที่รันบน CPU
[รายละเอียดทุกตัวเลขและทางตันที่เจอ → `bench/FINDINGS.md`](bench/FINDINGS.md)

## ฟีเจอร์

**อ่านเอกสาร**
- สลิปโอน · ใบเสร็จ · ใบเงินเดือน — จำแนกชนิดเองอัตโนมัติ
- ดึงยอดเงิน วันที่ เวลา เลขอ้างอิง ผู้โอน/ผู้รับ ธนาคาร
- รองรับ `.webp` (LINE ส่งมาแบบนี้) · ลายน้ำนูน · QR code · รูปถ่ายจากมือถือ
- ทุกผลลัพธ์มี `confidence` + `warnings` — **ค่าที่ไม่มั่นใจจะไม่ถูกบันทึกเงียบ ๆ**

**สมุดบัญชี**
- สรุปรายเดือน รายสัปดาห์ และทั้งหมด
- **กันบันทึกซ้ำ 3 ชั้น**: hash ไฟล์ (เช็ค*ก่อน* OCR) → เลขอ้างอิง → fuzzy จากยอด+เวลา
- เงินเก็บเป็น **integer สตางค์** ไม่ผ่าน float
- ตั้งงบ + เตือนงบเกิน + จับรายการประจำ + สรุปรายสัปดาห์
- พิมพ์ `กาแฟ 60` ในแชทก็บันทึกได้ — ใช้ rule ล้วน ไม่ต้องมีโมเดล
- เดาหมวดให้จากพจนานุกรมไทย แก้ได้ทีหลังด้วยปุ่มเดียว แล้วจำไว้ใช้ครั้งหน้า
- กรองรายการตามรายรับ/รายจ่าย ตามหมวด หรือเฉพาะที่ยังไม่จัดหมวด —
  และบอกตรง ๆ ว่าซ่อนไว้กี่รายการ ไม่ตัดทิ้งเงียบ ๆ

**ความเป็นส่วนตัว (PDPA)**
- จำกัดผู้ใช้ได้ด้วย `ALLOWED_USERS` — คนนอกถูกกั้นก่อนแตะ DB ก่อนเข้าคิว OCR
- ต้องกด **ยินยอม** ก่อนระบบถึงเริ่มเก็บอะไร
- **ไม่เก็บรูปสลิป** — เก็บแค่ SHA-256 ไว้กันบันทึกซ้ำ
- เลขบัญชีเก็บแค่ 4 ตัวท้าย
- `ลบข้อมูลของฉัน` ลบจริงทุกตาราง — มีเทสยืนยัน

## เริ่มใช้งาน

```bash
git clone https://github.com/<you>/thai-slip-ocr-line-bot.git
cd thai-slip-ocr-line-bot
cp .env.example .env          # เติม LINE_CHANNEL_SECRET + LINE_CHANNEL_ACCESS_TOKEN
docker compose up -d --build
```

แล้วตั้ง Webhook URL ใน LINE เป็น `https://โดเมนของคุณ/webhook`
[คู่มือ deploy เต็ม → `DEPLOY.md`](DEPLOY.md) · [ต้องกรอกอะไรบ้าง → `FILL-ME.md`](FILL-ME.md)

ไม่อยากใช้ Docker: `npm install && ./dev.sh`

## คำสั่งที่บอทเข้าใจ

| พิมพ์ | ผล |
|---|---|
| *(ส่งรูป)* | อ่านสลิป → บันทึก → ตอบการ์ด |
| `กาแฟ 60` | บันทึกรายจ่าย 60 บาท |
| `ได้เงินเดือน 30000` | บันทึกรายรับ |
| `สรุป` · `สรุปสัปดาห์` · `สรุปทั้งหมด` | ดูยอด |
| `รายการ` | ดู/ลบ/แก้ยอด/เปลี่ยนหมวดรายการล่าสุด |
| `รายการรายจ่าย` · `รายการ อาหาร` | **กรอง**เฉพาะรายจ่าย หรือเฉพาะหมวดนั้น |
| `งบ 20000` · `งบ อาหาร 5000` | ตั้งงบ |
| `ตั้งค่า` · `ข้อมูลของฉัน` · `ลบข้อมูลของฉัน` | จัดการข้อมูล |

ส่วนใหญ่กดปุ่มในการ์ดหรือเมนูล่างจอได้ — ออกแบบให้พิมพ์น้อยที่สุด

## โครงโปรเจกต์

```
src/            LINE bot — webhook, Flex card, สมุดบัญชี, NLU แบบ rule
ocr/            HTTP service ของ PaddleOCR + parser เอกสารไทย (stdlib ล้วน)
bench/          เครื่องมือวัดผล + บันทึกการวัดทั้งหมด
test/           123 เทส ไม่ต้องใช้เน็ตหรือ GPU — `npm test`
scripts/        สร้าง rich menu, cron สรุปรายสัปดาห์, sync ไฟล์ OCR, backup
assets/         รูปเมนูล่าง (2 หน้า สลับด้วยแท็บ) + RICHMENU-SPEC.md
```

parser ใน `ocr/` เป็น **Python stdlib ล้วน** (`re`, `json`, `difflib`) —
หยิบ `slip_parser.py` ไปใช้ในโปรเจกต์อื่นได้เลยโดยไม่ต้องลงอะไร

## Tech stack

| ส่วน | ใช้อะไร |
|---|---|
| Runtime ฝั่งบอท | **Node.js 22+** · ESM — ไม่มี build step ไม่มี TypeScript ไม่มี bundler |
| HTTP | **Express 5** |
| LINE | **`@line/bot-sdk` 11** |
| ฐานข้อมูล | **`node:sqlite`** — มากับ Node เอง ไม่ต้องคอมไพล์ native module |
| Config | `dotenv` |
| เทส | **`node:assert` + `node:test`** — ไม่มี jest ไม่มี vitest |
| Runtime ฝั่ง OCR | **Python 3.12** |
| OCR | **`paddleocr` 3.7** + `paddlepaddle` 3.3 (**CPU ล้วน ไม่มี torch ไม่มี CUDA**) |
| HTTP server ฝั่ง OCR | **`http.server` ของ stdlib** — ไม่มี FastAPI ไม่มี Flask |
| Parser เอกสาร | **`re` · `json` · `difflib`** — stdlib ล้วน |
| รูปภาพ | Pillow |
| Deploy | Docker Compose · `node:22-alpine` + `python:3.12-slim` |

**ฝั่งบอทมี dependency แค่ 3 ตัว และ devDependencies เป็นศูนย์:**

```json
"@line/bot-sdk"   "express"   "dotenv"
```

### สิ่งที่ตั้งใจ "ไม่ใช้" — และใช้อะไรแทน

| ไม่ใช้ | ใช้แทน |
|---|---|
| LLM / API เสียเงิน | regex + พจนานุกรม — `nlu.js` 92 บรรทัด · `categories.js` 120 บรรทัด |
| Postgres / MySQL | SQLite ที่ฝังอยู่ในโปรเซสของแอปเอง |
| ORM (Prisma, Drizzle) | SQL ดิบ + prepared statement |
| Redis | `Map` ในหน่วยความจำ — `ratelimit.js` 63 บรรทัด |
| TypeScript / bundler | JavaScript + JSDoc |
| jest / vitest | `node:assert` |

โค้ดที่เขียนเองจริง ๆ: **~3,000 บรรทัด JS** (`src/`) และ **~1,400 บรรทัด Python**
(`ocr/`) มี 123 เทสคุมไว้

**สิ่งที่แลกมาชัดเจน:** ความฉลาดด้านภาษาไทยทั้งหมดเป็นกฎที่เขียนมือ เจอรูปประโยคใหม่
ก็ต้องเติมกฎใหม่ ไม่ใช่โมเดลที่วางนัยทั่วไปเองได้ แลกกับการที่ทั้งระบบตอบ webhook
ใน ~3 ms กิน RAM 23 MB และไม่ต้องมี GPU — นิวรอลเน็ตเดียวในระบบคือโมเดล OCR ขนาด 7.8 MB

## เอาไป fork ต่อ

ส่วนที่หยิบไปใช้เดี่ยว ๆ ได้เลย:

- `ocr/slip_parser.py` — parser สลิปโอนไทย มี self-test ในตัว
- `ocr/payslip_parser.py` — parser ใบเงินเดือน มี fuzzy match ป้ายที่ OCR อ่านเพี้ยน
- `bench/eval_dataset.py` — วัดความแม่น OCR กับโฟลเดอร์สลิปของคุณเอง
- `src/flex.js` — ระบบการ์ด Flex ภาษาไทยที่ใช้ซ้ำได้

ถ้าเพิ่มธนาคารหรือแก้เคสที่ parser พลาด ยินดีรับ PR (แนบสลิปตัวอย่างที่ปิดข้อมูลส่วนตัวแล้ว + เทส)
